# FixPoint

Учебная система управления ремонтом. React 18 + TypeScript + Vite → REST API ASP.NET Core 8 → EF Core / PostgreSQL 16. JWT передаётся в Authorization; nginx или Vite проксирует /api.

## Запуск (Windows / Linux / macOS)
1. Установите и запустите Docker Desktop (или Docker Engine с Compose).
2. Распакуйте архив, откройте терминал в папке с compose.yaml.
3. Создайте `.env`: PowerShell `Copy-Item .env.example .env`, Bash `cp .env.example .env`. Замените значения пароля и JWT на собственные (JWT не менее 32 ASCII символов).
4. Выполните `docker compose up --build -d`.
5. Проверьте `docker compose ps`, при проблемах `docker compose logs -f api frontend`.
6. Откройте http://localhost:5173. Swagger: http://localhost:5080/swagger. Миграции применяются при старте API.

Остановка: `docker compose down`. Удаление БД (все данные): `docker compose down -v`.

## Проверка сценария
В учебной версии регистрация позволяет выбрать роль. Зарегистрируйте четыре аккаунта с разными email: клиент, менеджер, мастер, администратор. Клиент создаёт заявку. Выйдите, войдите менеджером, откройте заявку и назначьте мастера. Войдите мастером, начните диагностику, создайте смету, скопируйте ссылку для клиента. Откройте её в другом браузере или приватном окне. Задайте вопрос или запросите пересмотр. Мастер обновляет список, отвечает и при необходимости создаёт новую версию. Откройте новую ссылку и согласуйте смету. Мастер обновляет заявку и переводит её в ремонт, готовность и завершение. Администратор управляет ролями и услугами. Для отклонения используйте отдельную заявку и укажите причину.

## Разработка фронтенда
Запустите DB и API: `docker compose up --build -d db api`. В папке frontend выполните `npm install`, затем `npm run dev`. Откройте адрес, указанный Vite (обычно http://localhost:5173). `npm run build` проверяет TypeScript и собирает dist. Для этого нужен Node.js 22 и доступ к npm. Если порт занят, остановите соответствующий контейнер или используйте адрес Vite.

## Обновление v2
Добавлены позиции сметы с серверным расчётом стоимости, срок в днях, диагностика, журнал переходов и решений, уведомления кабинета, действия клиента из кабинета и SMTP через Mailpit. Для проверки писем откройте http://localhost:8025 после запуска Compose. Mailpit перехватывает письма локально, не доставляет их внешним адресатам. Очередь SMTP в памяти, без гарантии повторной доставки. Для обновления существующей установки выполните `docker compose up --build -d` (не удаляйте том БД). Новая SQL-миграция применяется при старте; snapshot EF требует синхронизации перед генерацией следующих миграций. История старых переходов не восстанавливается.

Проверка: создайте заявку, назначьте мастера, начните диагностику и сохраните результат, добавьте несколько позиций сметы, проверьте итог и письмо в Mailpit. Клиент может запросить пересмотр из кабинета или по ссылке; мастер создаёт новую версию. Проверьте историю, решения и уведомления. Публичные маршруты ограничены 60 запросами в минуту на IP.
